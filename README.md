# Берёста

**Русский** · [English](README.en.md)

**Берёста** (`beresta`) — XML-библиотека на **C++17** без единой сторонней зависимости. Она полностью заменяет Xerces-C++: DOM, SAX, пространства имён, кодировки, DTD, XML Schema, XPath 1.0, XInclude, обход дерева и сериализация.

Ядро собирается в динамическую библиотеку с плоским Си-интерфейсом. Поэтому «Берёстой» можно пользоваться не только из C++, но и из **C**, **Java 22+** (Project Panama, без JNI), **C#** (P/Invoke), **Python** (ctypes) и **Node.js** (Node-API, без node-gyp, с типами TypeScript), а сборка в **WebAssembly** работает в браузере, Web Workers и Cloudflare Workers. Готовые обёртки лежат в `bindings/`, а пакеты для npm, PyPI и NuGet со всеми платформами собирает CI (см. [Готовые пакеты и релизы](docs/building.md#готовые-пакеты-и-релизы)).

Название — от берестяных грамот: на бересте на Руси писали документы. Библиотека тоже работает с документами, только с XML.

```cpp
#include "beresta.hpp"

beresta::Document doc = beresta::XmlParser().parse("<greeting lang=\"ru\">Привет</greeting>");
std::cout << doc.getRoot()->getTextContent();                    // Привет
std::cout << beresta::xpath::evaluateString(doc, "/*/@lang");     // ru
std::cout << doc.toString();                                      // <greeting lang="ru">Привет</greeting>
```

## Преимущества

### Коротко
1. **Полный набор стандартов без зависимостей.** XML 1.0, пространства имён, восемь кодировок, DTD, XML Schema 1.0 с ключами и утверждениями `xs:assert` из XSD 1.1, весь XPath 1.0, XInclude, SAX, DOM Traversal — и ни одной сторонней библиотеки, даже iconv или ICU.
2. **Самое компактное дерево среди полноценных библиотек.** Каталог на 26 МБ занимает в памяти 172 МБ — против 248 МБ у libxml2 и 348 МБ у Xerces-C++ (см. [Производительность](docs/comparison.md#производительность)).
3. **Скорость полноценной библиотеки.** Разбор вдвое быстрее Xerces-C++, на тексте — почти наравне с libxml2. XPath быстрее libxml2, проверка по XSD в 1,8 раза быстрее Xerces-C++ — прямо во время разбора или потоком без дерева.
4. **Автономные узлы.** Узел создаётся без документа, переносится между документами без `importNode`/`adoptNode` и переживает документ, из которого его забрали. В C++ такого почти нигде нет (см. [сравнение](docs/comparison.md#сравнение-с-другими-библиотеками)).
5. **Безопасность по умолчанию.** Сущностные бомбы ограничены всегда, внешние ресурсы не загружаются без явного разрешения, регулярные выражения XSD работают за линейное время, а хеш-таблицы с ключами из документа защищены секретным ключом от атак через коллизии (hash flooding).
6. **Никакой рекурсии по дереву документа.** Разбор, копирование, сравнение, вывод, проверка по XSD и деструктор обходят дерево по явному стеку — глубокий документ не уронит процесс. Рекурсивны только сборка схемы и разборщики выражений (XPath, регулярные выражения XSD): они идут по тексту схемы или выражения, а не по дереву данных.
7. **Проверенность.** 159 модульных тестов, включая нагрузочные (20 потоков на общих дескрипторах, 50 000 переносов узлов, 50 000 атрибутов в теге, рекурсивная схема глубиной 10 000), 100 % применимых случаев W3C XML Conformance Test Suite, санитайзеры ASan/UBSan/LSan/TSan, фаззинг libFuzzer.
8. **Семь языков из одного бинарника и WebAssembly.** C++, C, Java (Panama), C# (P/Invoke), Python (ctypes), PHP (FFI) и Node.js (Node-API) — всё в комплекте, без JNI, node-gyp и пакетов из сети. Тот же API для браузера и Cloudflare Workers — пакет `beresta-wasm`.
9. **Обёртки, которые не тормозят на тяжёлой работе.** Разбор, XPath и проверка по схеме идут внутри ядра со скоростью C++. Потоковая проверка из Java, .NET, Python и PHP быстрее родных средств этих языков, а гигабайтная выгрузка проверяется в десятках мегабайт памяти. Разбор с проверкой XSD в .NET в 2,3 раза быстрее `XmlDocument`, XPath в Java в 1,4–1,8 раза быстрее JDK (см. [Производительность](docs/comparison.md#производительность)).
10. **Готовые пакеты для всех платформ.** `npm install beresta`, `pip install beresta`, `dotnet add package Beresta`: внутри уже лежат бинарники для Windows и Linux (x64, arm64) и универсальный для macOS (Intel и Apple Silicon) — компилировать ничего не нужно.
11. **Сообщения на русском и английском.** Язык выбирается при сборке и меняется во время работы, новый язык добавляется одним файлом.
12. **Читаемый код.** Короткие функции, маленькие файлы, двуязычные комментарии везде — библиотеку можно прочитать, проверить и доработать самостоятельно.

### Современный C++
- **Только `std::string` в UTF-8.** Нет `XMLCh`, `XMLString::transcode()` и ручного `release()`. Значения из дерева сразу подходят любому коду на C++.
- **RAII везде.** Родитель владеет детьми через `std::unique_ptr`, поэтому `delete`, `release()` и `XMLPlatformUtils::Initialize/Terminate` не нужны, а утечки невозможны по построению.
- **Узлы автономны.** Глобального менеджера документа нет. Узел создаётся обычным конструктором, живёт где угодно и переносится в любое дерево без `importNode`/`adoptNode`. Пространство имён узла вычисляется по его текущему месту в дереве, поэтому после переноса оно всегда верное для нового документа.
- **Глубокое копирование одной строкой:** `Element copy = original;`. Для копирования через базовый класс есть виртуальный `clone()`.
- **Типизированные настройки.** Вместо строковых «фич» `DOMConfiguration` — обычная структура `ParserOptions`, и опечатку в имени ловит компилятор.
- **Строгие гарантии исключений.** Если вставка, замена или присваивание не удались, дерево остаётся прежним, а переданный узел остаётся у вызывающего.

### Разбор
- **Один парсер — два режима.** SAX-ядро генерирует события, DOM строится одним из обработчиков (паттерн Builder). SAX так же строг, как DOM.
- **Формат ввода не важен.** Отформатированный и «сплошной» XML дают одно и то же дерево.
- **Разбор на `std::string_view`.** Для UTF-8 входной текст не копируется: сканер возвращает срезы исходной строки.
- **Итеративный разбор без рекурсии.** Открытые элементы и тексты сущностей хранятся в явных стеках, поэтому глубокий ввод не переполнит стек вызовов.
- **Нигде нет рекурсии по дереву.** Копирование, сравнение, сериализация (обычная и с отступами), сбор текста, `normalize`, проверка по XSD и даже деструктор обходят дерево по явному стеку. Деструктор разбирает дерево вовсе без выделения памяти. Глубина документа ограничена только памятью: тесты строят, копируют, сравнивают, выводят и разбирают дерево глубиной 100 000 уровней.
- **Позиции ошибок в символах UTF-8.** Координаты считаются инкрементально и только по запросу. Позицию любого узла можно запомнить (`trackLocations`).

### Полный набор стандартов
- **XML 1.0 (5-я редакция):** проходит **100 %** применимых случаев официального W3C XML Conformance Test Suite (2001 из 2585; остальные — XML 1.1 и случаи для редакций 1–4), см. [`tests/conformance`](tests/conformance/README.md). Символы имён — по таблицам 5-й редакции.
- **Namespaces in XML:** проверка при разборе и «живые» URI в DOM.
- **Восемь кодировок:** UTF-8, UTF-16 LE/BE, ISO-8859-1, US-ASCII, windows-1251, windows-1252, KOI8-R, IBM866. Кодировка определяется по BOM и декларации. Все таблицы написаны самостоятельно, без iconv и ICU.
- **DTD:** внутреннее и внешнее подмножества, параметрические сущности, условные секции, атрибуты по умолчанию, полная проверка валидности, `getElementById`.
- **XML Schema 1.0:** 45 встроенных типов, фасеты, `restriction`/`extension`, `list`/`union`, `sequence`/`choice`/`all`, группы, `xs:any`, группы замены, `xsi:type` с проверкой наследования, `block`/`final`, абстрактные элементы и типы, `xsi:nil`, ID/IDREF, ограничения идентичности `xs:key`/`xs:unique`/`xs:keyref`, `include`/`import`/`redefine`/`override`. Официальный W3C XML Schema Test Suite — **98,6 %** применимых случаев; расхождения и сознательные ограничения — в [`tests/xsts`](tests/xsts/README.md).
- **Из XML Schema 1.1:** утверждения `xs:assert` и `xs:assertion` на XPath 1.0 с частыми конструкциями XPath 2.0 (`if`, `some`/`every`, `eq`/`lt`…, `xs:decimal(…)`, `xs:date(…)`) и **точной десятичной арифметикой** (`0.10 + 0.20 = 0.30` — истина), `xs:override`, `vc:minVersion`/`vc:maxVersion`. Утверждений нет ни в Xerces-C++, ни в libxml2, ни в .NET.
- **XPath 1.0 целиком:** все 13 осей, включая `namespace`, все 27 функций базовой библиотеки, переменные и префиксы.
- **XInclude 1.0:** `parse="xml|text"`, `xi:fallback`, XPointer `element()` и по ID, защита от циклов.
- **DOM Traversal:** `TreeWalker` и `NodeIterator` с фильтрами — алгоритмы строго по спецификации W3C.

### Надёжность и безопасность
- **Защита от «billion laughs».** Лимиты на число, объём и вложенность раскрытий сущностей включены всегда, а не отдельной настройкой.
- **Нет XXE и SSRF по умолчанию.** Без явного `ResourceResolver` ничего внешнего не загружается. `FileResourceResolver` не выходит за корневой каталог и отвергает сетевые URI.
- **Защита от hash flooding.** Хеш-таблицы, ключи которых приходят из документа (значения ID, имена элементов и атрибутов), используют SipHash-1-3 со случайным ключом процесса: заранее подобрать строки с одинаковым хешем нельзя.
- **Нет квадратичных проверок на враждебном вводе.** Повторы атрибутов ищутся перебором только у тегов с несколькими атрибутами, дальше — хеш-таблицей. Тег со 100 000 атрибутов (1,3 МБ) разбирается за 0,07 с.
- **Своё регулярное выражение XSD на НКА Томпсона.** Время проверки линейно, «катастрофический бэктрекинг» невозможен в принципе.
- **Точная арифметика фасетов.** Десятичные числа сравниваются как строки цифр любой длины, без потери точности на `double`.
- **Проверено санитайзерами:** все тесты проходят под AddressSanitizer, LeakSanitizer, UBSan и `_GLIBCXX_ASSERTIONS` — без утечек памяти, неопределённого поведения и выхода за границы контейнеров, а под ThreadSanitizer — без гонок (20 потоков на общих схеме, XPath и документе).
- **Нагрузочные тесты под сценарии обёрток:** 50 000 переносов узлов между документами с проверкой каждого ранее выданного дескриптора после освобождения исходного документа; время разбора тега с 25 000 и 200 000 атрибутов растёт линейно; рекурсивная схема глубиной 10 000 уровней проверяется одинаково в SAX, DOM и по готовому дереву.
- **Индекс ребёнка за O(1).** Узел хранит свой номер среди соседей, поэтому `nextSibling`, `removeChild` последнего ребёнка и перенос узлов из обёрток не ищут узел перебором: 150 000 переносов из Си-интерфейса занимают 13 мс.
- **Проверено фаззингом:** три цели libFuzzer (разбор с любыми `ParserOptions`, XPath, XML Schema) под ASan + UBSan; последний раунд — ни одной находки, см. [`tests/fuzz`](tests/fuzz/README.md).

### Вывод
- **Компактный по умолчанию.** Ни одного лишнего пробела, порядок атрибутов сохраняется, повторный разбор вывода даёт тот же текст.
- **Красивый вывод по запросу.** Отступы ставятся только там, где они не меняют данные: смешанное содержимое выводится дословно.
- **Любая выходная кодировка.** Декларация сама получает правильный `encoding`, BOM пишется при необходимости, а символы вне кодировки становятся `&#N;`.

### Один бинарник — семь языков
- **Плоский Си-интерфейс** (`extern "C"`, 71 функция): стабильный ABI, имена без декорирования, объекты наружу — непрозрачные дескрипторы `void*`. Исключения C++ никогда не пересекают границу библиотеки.
- **Java 22+ через Project Panama** (Foreign Function & Memory API): ни строчки JNI, Java работает с нативной памятью напрямую. Бинарник едет внутри jar и сам извлекается под нужную ОС и архитектуру.
- **C# через P/Invoke** с `SafeHandle`: память освобождается детерминированно (`using`) и гарантированно (при финализации). Пакет NuGet со стандартной раскладкой `runtimes/<rid>/native`.
- **Python через ctypes:** ни одного пакета из PyPI и ни одного компилятора на машине пользователя.
- **PHP 8.2+ через FFI:** пакет Composer без своего расширения PHP. Классы `Beresta\Parser`, `Beresta\Document`, `Beresta\XPath`, `Beresta\Schema` выглядят как обычный PHP: `foreach` по детям, атрибуты через `$element['code']`, `clone $document`. Для PHP-FPM есть загрузка в `opcache.preload`.
- **Node.js через собственный аддон Node-API:** без `ffi-napi`, node-gyp и npm-зависимостей; готовый бинарник едет в пакете, типы TypeScript — в комплекте.
- **WebAssembly** (`bindings/wasm`, пакет `beresta-wasm`): то же ядро, собранное Emscripten, и тот же JS-слой, что у Node.js, — DOM, XPath и XSD в браузере, Web Workers и Cloudflare Workers. Модуль весит около 650 КБ (около 250 КБ в gzip).
- **Универсальный бинарник для macOS:** `make universal` склеивает сборки x86_64 и arm64 через `lipo`, CMake делает то же с `CMAKE_OSX_ARCHITECTURES="x86_64;arm64"`.
- **Тяжёлая работа — внутри ядра.** XPath (`selectValues` без объектов-узлов), проверка по схеме и потоковая проверка файлов любого размера вызываются из любого языка одним вызовом, и через границу языка проходит только результат.
- **Сборка сама раскладывает бинарник.** CMake и Makefile определяют ОС и архитектуру процессора и копируют библиотеку в ресурсы Maven-проекта, в `runtimes/<rid>/native` для .NET, в пакеты Python и Composer и (аддоном) в пакет npm.
- **Наружу видны только функции Си-интерфейса** — ровно 71 символ. Классы C++ скрыты (`-fvisibility=hidden`, на Windows экспортируется только `BERESTA_API`). C++ runtime встроен в библиотеку, поэтому на чистой машине не нужны ни `libstdc++`, ни `vcruntime`. На Linux символы встроенной `libstdc++` тоже спрятаны (`--exclude-libs,ALL`): в процессе JVM или Python они не конфликтуют с системной `libstdc++`.

### Инженерные качества
- **Ноль зависимостей:** только стандартная библиотека C++17. Обёрткам тоже ничего не нужно, кроме JDK, .NET, Python, PHP или Node.js.
- **Кроссплатформенность:** Windows, Linux, macOS, WebAssembly. Компиляторы MSVC, MinGW, GCC, Clang, Emscripten. Есть CMake и Makefile с автозависимостями, а CI в GitHub Actions собирает и проверяет всё это на каждый push.
- **Тип узла без `dynamic_cast` в ядре:** тип определяется через `getType()`, приведение — `static_cast`. Только Си-интерфейс проверяет дескрипторы через `dynamic_cast`: текстовый узел вместо элемента даёт ошибку `INVALID_ARGUMENT`, а не неопределённое поведение.
- **Сообщения на двух языках:** все тексты ошибок — в каталоге сообщений, русский и английский в комплекте. Язык по умолчанию выбирается при сборке, во время работы его меняет одна функция, а новый язык добавляется одним файлом.
- **Читаемый код:** короткие функции и небольшие файлы, подробные двуязычные комментарии (русский и английский), классические паттерны (Composite, Template Method, Builder, Facade, Strategy, Interpreter, Observer, Factory Method, Adapter).

## Кто что делает

«Берёста» создаётся человеком вместе с двумя языковыми моделями. Решения принимает человек, а модели
работают по его заданиям. Каждую правку проверяют тесты и наборы W3C.

| Участник | Роль |
|---|---|
| **Ермаков Алексей Александрович** — автор и правообладатель | Основная идея и замысел проекта, постановка задач и решения. Создание и редактирование правил генерации кода для обеих моделей. Проверка кода в отладчике, поиск ошибок. Человеческий анализ документации, кода библиотеки и тестов: что проверяет случай W3C, верно ли поведение, где ожидание набора спорно. |
| **Claude** (Anthropic), ассистент в Claude Code | Архитектура и проектирование модулей. Реализация большей части кода: парсер, DTD, XPath, XML Schema, Си-интерфейс и обёртки. Сверка поведения со спецификациями W3C, диагностика ошибок, прогонщики наборов W3C, сборка и выпуск, документация. Проверка кода локальной модели. |
