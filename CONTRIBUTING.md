# Как участвовать в разработке

Русский | [English](CONTRIBUTING.en.md)

Спасибо, что хотите помочь «Берёсте»! Сообщения об ошибках, тесты, исправления, обёртки и переводы одинаково ценны. Участвуя, вы соглашаетесь с [кодексом поведения](CODE_OF_CONDUCT.md). Об уязвимостях пишите закрыто — см. [SECURITY.md](SECURITY.md).

## Где

Основной репозиторий — [GitHub](https://github.com/ErmaleyAlekov/beresta), зеркало — [Gitverse](https://gitverse.ru/ermaleyalekov/beresta). Задачи и запросы на слияние принимаются на обеих площадках; сопровождающий переносит принятые изменения в обе.

## Сообщение об ошибке

- Версия (`beresta_version()` или `BERESTA_VERSION_STRING`), ОС, компилятор или язык обёртки.
- Минимальный XML / XSD / XPath, на котором ошибка повторяется, ожидаемый и фактический результат.
- Для ошибок соответствия — ссылка на пункт спецификации (XML 1.0, Namespaces, XSD 1.0 / 1.1, XPath 1.0) или на случай W3C-набора.

## Изменение кода

1. Сделайте форк и ветку от `main`.
2. Соберите и запустите тесты — инструкции в [docs/building.md](docs/building.md):

```bash
make test
```

3. Для изменений XSD прогоните W3C XML Schema Test Suite, для парсера — W3C XML Conformance (см. [docs/development.md](docs/development.md#тесты)): процент не должен падать.
4. Добавьте тест на исправленную ошибку или новую возможность: модульный тест в `tests/src/<модуль>/` и его регистрацию.
5. Откройте запрос на слияние в `main`: что изменено, почему, как проверено. CI должен быть зелёным.

## Правила кода

Проект придерживается строгих правил написания кода. Каждый запрос на слияние рассматривается сопровождающим лично.

Подробнее об устройстве проекта и о том, как добавить тип узла, функцию XPath или тип XSD, — в [docs/development.md](docs/development.md#расширение-библиотеки).

## Документация

Каждый документ есть на русском (`*.md`) и английском (`*.en.md`); меняя один, поправьте и второй. Заметные изменения добавляйте в раздел будущей версии [CHANGELOG.md](CHANGELOG.md) и [CHANGELOG.en.md](CHANGELOG.en.md).
