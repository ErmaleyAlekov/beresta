# Прогон W3C XML Schema Test Suite (XSTS)

Прогонщик проверяет «Берёсту» на официальном наборе W3C для XML Schema 1.0
(`xsts-2007-06-20`, каталог `xmlschema2006-11-06`: 39 420 случаев в 14 383
группах от NIST, Sun, Microsoft и Boeing). Сам набор в репозиторий не
кладётся (`.gitignore` рядом), его скачивает `make fetch`.

## Запуск

```bash
cd tests/xsts
make fetch      # скачать (4,4 МБ, curl) и распаковать набор в xmlschema2006-11-06/
make run        # собрать библиотеку и прогонщик, прогнать, записать xsts_report.md
```

То же через CMake (MSVC, MinGW, GCC, Clang):

```bash
cmake -S tests/xsts -B build-xsts
cmake --build build-xsts --config Release --target xsts_run
```

Отладка одной группы: `bin/xsts_runner xmlschema2006-11-06 --only MS-Element2006-07-15/elemZ012 --verbose`
(`--only` — префикс «набор/группа»). Код возврата 0 — прогон выполнен
(расхождения — в отчёте), 2 — сбой окружения. Весь набор проходит за ~7 с.

## Как выносится вердикт

Метаданные (`suite.xml` и файлы `*.testSet`) читает сама «Берёста».

| Случай | Что делает прогонщик | Пройден, если |
|---|---|---|
| `schemaTest`, valid | `Schema::fromDocuments` с `FileResourceResolver` (корень — каталог набора) | схема загрузилась |
| `schemaTest`, invalid | то же | библиотека отвергла схему (`DomException`) |
| `instanceTest`, valid | разбор (`preserveWhitespaceText`, внешний DTD) и `SchemaValidator::validate` по схеме группы | ни одной ошибки проверки |
| `instanceTest`, invalid | то же | хотя бы одна ошибка или документ не well-formed |

Подробности:

- схема из нескольких документов загружается через документ-«драйвер»
  (`xs:import` / `xs:include` каждого файла) — так документ, который другой
  документ набора подключает сам, загружается один раз;
- у групп без `schemaTest` схема берётся из подсказок `xsi:schemaLocation`
  экземпляра; у остальных подсказки добавляются к схеме группы только для
  пространств имён, которых в ней нет (явно заданная схема важнее подсказки,
  как в Xerces и System.Xml);
- если схема группы не загрузилась, экземпляры считаются проваленными
  (нечем проверять), а при ожидаемо невалидной схеме — пропущенными;
- исключение не из библиотеки (`std::bad_alloc` и т. п.) — всегда провал.

## Что пропускается и что считается отдельно

- **Пропуск** — спорные случаи (`status="queried"`, 793): рабочая группа W3C не
  подтвердила их ожидание. Случаев с атрибутом `version` не для 1.0 в этом
  выпуске набора нет.
- **Ограничение** — случаи из `known_limitations.txt`: строка «ключ набор/группа[/случай]».
  Случай из списка всё равно прогоняется: прошёл — считается прошедшим,
  провал попадает в графу «Ограничение» и в процент не входит.

| Ключ | Причина | Случаев |
|---|---|---:|
| `particle-restrict` | корректность ограничения модели (cos-particle-restrict) не проверяется — сознательное ограничение из README | 260 |
| `upa` | однозначность модели (UPA) не проверяется — сознательное ограничение | 17 |
| `redefine-restrict` | `xs:redefine` без ссылки на себя не проверяется как ограничение прежней группы (src-redefine.6.2, 7.2) — следствие того же ограничения | 14 |
| `duration-order` | у `duration` нет порядка для фасетов-границ — сознательное ограничение | 13 |
| `unresolved-location` | недоступный `schemaLocation` — ошибка загрузки (спецификация разрешает пропуск) | 13 |
| `s4s-namespace` | схемы с `targetNamespace` самого XML Schema (схема для схем) не загружаются | 3 |
| `redefine-cycle` | циклы через `xs:redefine` (A переопределяет B, а B переопределяет или включает A) | 3 |
| `nested-derivation` | тип, выведенный из составного типа внутри его же модели, считается циклическим | 1 |
| `disputed` | ожидание набора расходится со спецификацией или зависит от процессора (ниже) | 29 |

Списки `particle-restrict` и `upa` собраны по описаниям групп
(«Particle Derivation OK», «NameAndTypeOK», «non-deterministic» и т. п.) только
из провалов вида «ошибочная схема принята»; остальное — разбором вручную.

### Спорные случаи (`disputed`)

| Случаи | Ожидание набора | Почему спорно |
|---|---|---|
| `ste110` | циклический union (`st` → `st2` → `st`) допустим | st-props-correct.2 запрещает циклы определений |
| `elemE002`…`elemE005` | шаблон `[0-9]{,5}` допустим | в грамматике регулярных выражений XSD 1.0 квантификатора `{,n}` нет |
| `stZ043` и ещё 19 случаев gMonth | `--12--` — верное значение gMonth | это запись 1-й редакции; во 2-й (по ней идёт набор) — `--MM` |
| `particlesIg003.v` | `xsi:type` допустим при `block="restriction"` у элемента типа anyType | тип из xsi:type выведен через неявное ограничение anyType, а Type Derivation OK (Complex), п. 1 запрещает такой шаг (так же считает Xerces) |
| `isDefault060_2.i` | невалиден пустой элемент с `default="5"` и `xsi:type` (int ≤ 6) | по cvc-elt.5.1 значение по умолчанию подставляется и проходит проверку |
| `mgO013` | схема валидна, экземпляр с `e1` — нет | переопределение без ссылки на себя не является ограничением прежней группы (`maxOccurs="0"`), а с действующей группой экземпляр валиден |
| `schA7.i` | подсказка `xsi:schemaLocation` для нового пространства имён игнорируется | учитывать ли подсказки — на усмотрение процессора; Sun (`ST_targetNS…`) ждёт обратного |

Каталоги в фокусе: `msData/element` 85,3 % → 94,8 %, `sunData/ElemDecl`

Оставшиеся провалы с этими метками — не в самих возможностях: уникальность
`id` и набор атрибутов в документе схемы, ограничение подстановочных атрибутов
(`ctO004`…), лексика дат и `duration`, `fixed` у смешанного содержимого.

## Остальные расхождения (вне новых возможностей)

Это направления для дальнейшей работы; каждое видно в `xsts_report.md`.

- **Регулярные выражения** (~710): блоки Unicode `\p{IsBasicLatin}` и т. п. и
  категории `\p{M}`, `\p{Mn}`… неизвестны (638 случаев — схема не загружается);
  неверно сопоставляются некоторые шаблоны (`\s+`, `\x41`, `A`, `[\d]` и `[\i]`
  вне ASCII).
- **Проверка документа схемы по схеме для схем** (большая часть 1 430
  «ошибочная схема принята»): лексика и уникальность `id`, допустимые
  атрибуты и дети (`xs:redefine namespace=…`, `xs:notation` с содержимым),
  `form` / `elementFormDefault`, корректность значений `default` / `fixed` по
  типу, ограничения фасетов и простых типов, ограничение подстановочных атрибутов.
- **Значения** (~270 «невалидный экземпляр принят»): лексика `duration`
  (`P`, `PT`), `dateTime` со знаком `+`, `gMonthDay` `--02-30`, `fixed` у
  смешанного и `anyType` содержимого, ограничения идентичности.
- **`minOccurs` / `maxOccurs` больше 2³¹** (15) отвергаются как некорректные.
- **`processContents`** хранится один на тип: у модели с двумя `xs:any`
  (strict и lax) действует последний (wildI005…007).
- `schZ012_*` — сравнение файловых URI без учёта регистра (особенность Windows).
