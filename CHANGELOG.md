## 2.2.0 — 2026-10-26

Новая обёртка для PHP и строгая проверка документа схемы: W3C XML Schema Test Suite — **98,6 %**
применимых случаев (в 2.1.4 — 96,2 %), провалов 1 463 → 515, новых нет. Защита от переполнения стека
на глубоко вложенных схемах и выражениях XPath. Схемы, отвергавшиеся раньше по ошибке (рекурсивная модель
с наследованием), загружаются; схемы, принимавшиеся раньше без проверки фасетов, атрибутов и порядка детей,
теперь могут быть отвергнуты — сообщение укажет строку и правило.

### XML Schema: рекурсивная модель и наследование

- Исправлено ложное «циклическое наследование типа» для схем вида Composite: тип-контейнер содержит
  элементы, чей тип расширяет сам контейнер (`BoxType` содержит `Panel`, `PanelType` расширяет `BoxType`).
  Раньше результат зависел от алфавитного порядка имён элементов. Производный тип теперь ждёт, пока
  достроится база, и получает её модель полностью; настоящие циклы (`A` → `A`, `A` → `B` → `A`) по-прежнему
  ошибка схемы.

### PHP-обёртка через FFI

- Новый пакет Composer `bindings/php` (`ermaleyalekov/beresta`, PHP 8.2+, расширение `ffi`): все 71 функция
  Си-интерфейса и классы `Beresta\Parser`, `Document`, `Node`, `Element`, `XPath`, `Schema`, `Diagnostic`.
  Узлы перебираются в `foreach`, атрибуты читаются как `$element['code']`, `clone $document` — глубокая копия.
- Загрузка для PHP-FPM / Apache в `opcache.preload` (`Beresta\Beresta::preload()`).
- Сборка: `make PHP=1`, `cmake -DBERESTA_BUILD_PHP=ON`; самопроверка `make PHP=1 php-test` — свой прогонщик без PHPUnit.

### XML Schema: проверка документа схемы

Исправления найдены ручной отладкой провалов W3C XML Schema Test Suite
(`tests/xsts_failing`). Итог набора — **98,2 %** (было 96,2 %): 792 случая исправлено, новых провалов нет
(234 — правками ниже, 558 — правилами фасетов и атрибутов и выбором объявления, следующий раздел).

- `minOccurs`/`maxOccurs` — любое неотрицательное целое: число длиннее 9 цифр больше не считается ошибкой.
- У `xs:all` `minOccurs` и `maxOccurs` — только 0 или 1.
- `id` у элементов XSD — NCName, уникальный в документе схемы.
- `xs:annotation` — не больше одной и только первым ребёнком (глобальные компоненты и частицы).
- Внутри `xs:group` — одна модель `sequence`/`choice`/`all`. Ссылка `xs:group` стоит только в модели или прямо в типе.
- `name` глобального компонента — NCName (с символами Юникода).
- Глубина сборки схемы ограничена: больше 256 уровней объявлений, типов и моделей — ошибка схемы
  `SCHEMA_TOO_DEEP`. Раньше предел частиц начинался заново на каждом анонимном типе, и при поднятом
  `maxDepth` схема примерно из тысячи вложенных элементов роняла процесс переполнением стека.
- Документ схемы глубже 1024 уровней элементов отвергается до сборки (`SCHEMA_DOCUMENT_TOO_DEEP`).
- README и сравнение: «никакой рекурсии» уточнено — нет рекурсии по дереву документа. Сборка схемы и разбор
  выражений рекурсивны, их пределы описаны.

### XML Schema: фасеты, атрибуты и объявление по частице

- Фасеты простых типов проверяются при загрузке схемы (часть 2, §4.3): фасет применим к базовому типу
  (`totalDigits` у строки, `length` у числа, `enumeration` у boolean — ошибки), значения границ и перечисления —
  значения базового типа, `totalDigits` > 0, `length` не в одном шаге с `minLength`/`maxLength`, `min*` не больше
  `max*`, две нижние или две верхние границы в одном шаге нельзя, ограничение не ослабляет базу (границы,
  длины, цифры, у целых `fractionDigits` = 0, `whiteSpace`), фасет не повторяется в шаге. Новые сообщения
  `SCHEMA_FACET_*`.
- `xs:attribute`: у глобального объявления нет `use`, `form`, `ref`; `use` — только optional/required/prohibited;
  с `default` допустим лишь `use="optional"` (`fixed` с `required`/`prohibited` по-прежнему допустим); ровно одно
  из `name` и `ref`, у ссылки нет `type`, `form` и вложенного типа; `type` и вложенный `xs:simpleType` вместе нельзя;
  имя — NCName, не `xmlns`, пространство имён — не xsi.
- `xs:all` не содержит `sequence`/`choice`/`all` и сама не стоит внутри `sequence`/`choice` (в том числе через
  ссылку на группу). `xs:any` и ссылка на группу внутри `xs:all` допустимы, как в XSD 1.1.
- Ребёнок элемента проверяется по объявлению частицы модели, которая его приняла, а не по первому одноимённому
  объявлению: одноимённые элементы с разными `fixed` или типами и элемент, принятый `xs:any`, проверяются верно;
  у каждого `xs:any` свой `processContents` (раньше на весь тип действовал последний).
- Атрибут с `use="prohibited"` допускается `xs:anyAttribute` типа, если тот разрешает его пространство имён.
- `fixed` и перечисление у union и list сравниваются по значению: значение union принадлежит первому подходящему
  члену (`fixed="1"` равно `true` у union(boolean, int)), у list сравниваются элементы.
- Тест `xsd_advanced_tests` опирался на схему с группой `xs:all` внутри `xs:sequence` — она недопустима
  (cos-all-limited), тест переписан. В `tests/xsts/known_limitations.txt` ключ `disputed` дополнен случаями, где
  набор ждёт записи gMonth 1-й редакции в фасетах и ограничений NMTOKENS / positiveInteger, запрещённых §4.3.

### XPath

- Глубина вложенности выражения ограничена: больше 128 уровней скобок, аргументов функций и предикатов
  (а в утверждениях XSD — и ветвей `if`, кванторов) — ошибка разбора `XPATH_ERROR`. Раньше выражение
  примерно из тысячи вложенных скобок роняло процесс переполнением стека.
- Длинная цепочка операторов (`1+1+…+1`, `a | b | …`, `x or y or …`) вычисляется и освобождается циклом:
  раньше цепочка из нескольких тысяч операторов роняла процесс переполнением стека.

### Инструменты

- `tests/xsts_failing` — отладчик провалов XSTS: список провалов из прогона, выполнение случаев по одному
  (фильтр, `--case N`, `--stop-on-first`), отладочная сборка вместе с библиотекой.

### XML Schema: значения по типу, аннотации и нотации

Итог W3C XML Schema Test Suite — **98,6 %**: провалов 671 → 515, новых нет.

- `default` и `fixed` элементов и атрибутов проверяются по типу при загрузке схемы. У элемента с составным типом
  значение допустимо при простом (проверка по нему) или смешанном содержимом; при пустом или только элементах —
  ошибка. Новые сообщения `SCHEMA_VALUE_CONSTRAINT_INVALID`, `SCHEMA_VALUE_CONSTRAINT_CONTENT`.
- У `xs:element` атрибут `type`, вложенный `xs:simpleType` и вложенный `xs:complexType` взаимно исключают друг друга
  (`SCHEMA_ELEMENT_PARTS_CONFLICT`).
- Порядок детей проверяется у каждого элемента документа схемы, а не только у глобальных компонентов и частиц:
  `xs:annotation` одна и первая также в `xs:key`, `xs:selector`, `xs:field`, `xs:list`, `xs:union`, `xs:extension`,
  `xs:anyAttribute` и неиспользуемых определениях. Внутри `xs:annotation` — только `xs:appinfo` / `xs:documentation`.
- `xs:notation`: только прямо в `xs:schema`, внутри — только аннотация; имя — NCName без повторов; нужен
  `public` или `system` (`SCHEMA_NOTATION_NO_IDENTIFIER`).
- Правила XSD 1.0, отменённые в 1.1 (`xs:any` внутри `xs:all`, `default`/`fixed` у типа ID), не применяются:
  «Берёста» — процессор 1.1. В `tests/xsts/known_limitations.txt` — новый ключ `xsd11-rules` (7 случаев); в
  `disputed` добавлены 3 группы с `fixed` gMonth в записи 1-й редакции.

  компилятор, итог по шагам и число пройденных тестов). Описание — `tools/stand/README.md`.

## 2.1.2 — 2026-10-20

Проверка XML Schema по итогам W3C XML Schema Test Suite: **93,6 % → 96,2 %** применимых случаев.

### Регулярные выражения XSD

- Категории `\p{..}` и блоки `\p{Is..}` / `\P{..}` — по Unicode 3.1 (версия, на которую ссылается
  XSD 1.0), из собственных таблиц без ICU; генератор `tools/unicode/generate_unicode_tables.py`.
- `\d` = `Nd`, `\w` — всё, кроме `P`, `Z`, `C`; `\i` и `\c` — по приложению B XML 1.0.
- Строгий синтаксис XSD 1.0: неизвестные экранирования (`\x41`, `\A`, `\b`, `\1`), обратный диапазон,
  пустой класс и `[` без экранирования внутри класса — ошибка схемы; `\p{Cs}` и неизвестные имена — тоже.
- XSTS 93,6 % → 95,7 %, в группе MS-Regex провалов нет (было 776).

### Значения и подстановочные атрибуты

- Частичный порядок `xs:duration` (3.2.6.2) в фасетах-границах.
- `xs:anyAttribute` по 3.4.2 / 3.10.6: пространства имён, пересечение, объединение при расширении,
  lax / strict по глобальным атрибутам, cvc-complex-type.5; `xs:anyType` — встроенный составной тип.
- `fixed` у смешанного содержимого, `xsi:nil` (cvc-elt.3), ID / IDREF у атрибутов по умолчанию,
  `xs:all` с `maxOccurs="0"`.

### Ограничения идентичности

- Поля `xs:key` / `xs:unique` видят атрибуты `default` / `fixed`, которых нет в экземпляре, — и в потоке,
  и при проверке по дереву.
- Поле на элемент составного типа без простого содержимого — ошибка `KEY_FIELD_COMPLEX`,
  на атрибут без типа (skip / lax) — `KEY_FIELD_UNTYPED`.
- `QName` / `NOTATION` в ключах сравниваются по паре «URI + локальное имя».
- XSTS 95,7 % → 96,2 %.

### Выпуск

- Релиз выходит одновременно на GitHub и Gitverse; пакеты в реестрах (npm, PyPI, NuGet, Maven Central)
  публикуются только из GitHub. Порядок — в [docs/building.md](docs/building.md#выпуск-версии).
