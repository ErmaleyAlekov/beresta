# Политика безопасности

Русский | [English](SECURITY.en.md)

«Берёста» разбирает XML из недоверенных источников, поэтому ошибки безопасности для нас — самые важные.

## Поддерживаемые версии

Исправления выходят в последней минорной ветке.

| Версия | Поддержка |
|---|---|
| 2.1.x | ✅ исправления безопасности |
| < 2.1 | ❌ обновитесь до 2.1.x |

## Как сообщить об уязвимости

**Не открывайте публичную задачу (issue) и не пишите в обсуждения** — так уязвимость станет известна раньше исправления.

Сообщите закрыто через GitHub: [Security → Report a vulnerability](https://github.com/ErmaleyAlekov/beresta/security/advisories/new). Если доступа к GitHub нет — по электронной почте [ermaley.alekov@yandex.ru](mailto:ermaley.alekov@yandex.ru) с темой «Безопасность: beresta».

В сообщении укажите:

- версию «Берёсты» и способ подключения (C++, Си-интерфейс, Java, C#, Python, Node.js, WebAssembly);
- ОС, компилятор или среду выполнения;
- минимальный XML / XSD / XPath, на котором проявляется ошибка, и что происходит (падение, зависание, рост памяти, чтение файла, сетевой запрос);
- если есть — оценку последствий.

## Что дальше

- Подтверждение получения — в течение 7 дней.
- Оценка и план исправления — в течение 30 дней; о сроках сообщим заранее.
- Исправление выходит патч-версией на GitHub и Gitverse и в пакетах npm, PyPI, NuGet и Maven Central; в [CHANGELOG.md](CHANGELOG.md) и в описании GitHub Security Advisory будет указан автор сообщения (если он не против).

## Что считается уязвимостью

Защита в «Берёсте» включена по умолчанию, и её обход — уязвимость:

- загрузка внешних ресурсов (DTD, сущности, XInclude, `xs:include` / `xs:import`) без явно переданного `ResourceResolver` (XXE, SSRF), выход `FileResourceResolver` за корневой каталог;
- обход лимитов сущностей (сущностные бомбы) и лимитов глубины;
- нелинейное время на регулярных выражениях XSD, на атрибутах и ключах (hash flooding), на XPath;
- падение, выход за границы памяти, утечка или неопределённое поведение на любом входном документе, схеме или выражении XPath;
- ошибки Си-интерфейса и обёрток, ведущие к тому же.

Не уязвимость: поведение при явно разрешённой загрузке ресурсов через свой резолвер, отказ в проверке по сознательным ограничениям (см. [docs/comparison.md](docs/comparison.md#ограничения)), ошибки соответствия стандарту без влияния на безопасность — о них пишите в обычные задачи.
